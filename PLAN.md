# План реализации кнопок AI-анализа

На основании [PROJECT.md](./PROJECT.md): приложение получает URL англоязычной статьи, парсит её и по выбранной кнопке подключает AI для генерации нужного ответа.

## Текущее состояние

| Компонент | Статус |
|-----------|--------|
| Поле ввода URL | ✅ Готово |
| Кнопки «О чем статья?», «Тезисы», «Пост для Telegram» | ✅ Работают с AI |
| Парсинг HTML (`date`, `title`, `content`) | ✅ `lib/parse-article.ts` |
| Блок «Результат» | ✅ Показывает ответ AI |
| AI для трёх кнопок из PROJECT.md | ✅ `lib/generate-article-action.ts` |
| OpenRouter + DeepSeek | ✅ `lib/openrouter.ts` |
| Деплой production | ✅ https://referent-pi.vercel.app |

---

## Порядок действий

### Шаг 1. Вынести общий клиент OpenRouter

**Цель:** не дублировать код запросов к API.

**Действия:**
1. Создать `lib/openrouter.ts`:
   - чтение `OPENROUTER_API_KEY` и `OPENAI_BASE_URL` из `.env.local`;
   - функция `callOpenRouter(messages, options?)` → строка ответа;
   - модель по умолчанию: `deepseek/deepseek-chat`;
   - обрезка текста статьи до лимита (например, 20 000 символов).
2. Перенести общую логику из `lib/translate-article.ts` в `lib/openrouter.ts`.
3. Упростить `lib/translate-article.ts` — оставить только промпт перевода.

**Результат:** единая точка вызова AI для всех кнопок.

---

### Шаг 2. Модуль генерации ответов по типу действия

**Цель:** одна функция — разные промпты для каждой кнопки.

**Действия:**
1. Создать `lib/generate-article-action.ts`.
2. Определить тип действия:

```ts
type ArticleAction = "summary" | "theses" | "telegram";
```

3. Для каждого действия — свой system/user prompt:

| Действие | Кнопка | Что должен вернуть AI |
|----------|--------|------------------------|
| `summary` | О чем статья? | Краткое описание на русском: тема, основная мысль, для кого полезна (2–4 абзаца) |
| `theses` | Тезисы | Список ключевых тезисов на русском (5–10 пунктов, маркированный список) |
| `telegram` | Пост для Telegram | Готовый пост на русском: заголовок, текст, 1–3 абзаца, без markdown-заголовков H1 |

4. На вход передавать распарсенную статью: `title`, `date`, `content`.
5. Возвращать только текст ответа, без пояснений модели.

**Результат:** `generateArticleAction(article, action) → string`.

---

### Шаг 3. Подключить AI в API-маршрут

**Цель:** кнопки из PROJECT.md вызывают генерацию, а не показывают JSON.

**Действия:**
1. Открыть `app/api/analyze/route.ts`.
2. После `fetchAndParseArticle(url)` добавить ветки:

```
action === "summary"   → generateArticleAction(parsed, "summary")
action === "theses"    → generateArticleAction(parsed, "theses")
action === "telegram"  → generateArticleAction(parsed, "telegram")
```

3. Вернуть единый формат ответа:

```json
{
  "result": "текст от AI",
  "mode": "generated",
  "action": "О чем статья?"
}
```

4. Оставить отдельную ветку для `translate` (уже реализована).
5. Убрать возврат JSON парсинга для трёх основных кнопок (или оставить `parsed` только для отладки).

**Результат:** API обрабатывает все действия из PROJECT.md.

---

### Шаг 4. Обновить интерфейс

**Цель:** показывать сгенерированный текст в блоке «Результат».

**Действия:**
1. Открыть `app/components/referent-form.tsx`.
2. Добавить режим отображения `mode: "generated"` (аналогично `translation`).
3. Для `summary`, `theses`, `telegram`:
   - показывать текст от AI в блоке «Результат»;
   - `whitespace-pre-wrap` для сохранения абзацев и списков.
4. Обновить текст загрузки:
   - «О чем статья?» → «Анализируем статью...»
   - «Тезисы» → «Формируем тезисы...»
   - «Пост для Telegram» → «Готовим пост...»
5. При необходимости убрать кнопку «Перевод» из основного UI или оставить как дополнительную (не входит в PROJECT.md).

**Результат:** пользователь видит осмысленный ответ, а не JSON.

---

### Шаг 5. Промпты и качество ответов

**Цель:** стабильный формат вывода для каждой кнопки.

**Действия:**
1. **«О чем статья?»** — попросить модель отвечать на русском, кратко, без пересказа каждого абзаца.
2. **«Тезисы»** — явно указать формат: нумерованный или маркированный список, один тезис — одна строка.
3. **«Пост для Telegram»** — ограничить длину (до ~1500 символов), живой тон, без канцелярита, эмодзи по желанию (0–2).
4. Прогнать 2–3 реальные англоязычные статьи и подправить промпты.
5. Обработать случай пустого `content`: понятная ошибка «Не удалось извлечь текст статьи».

**Результат:** предсказуемые ответы для разных сайтов.

---

### Шаг 6. Обработка ошибок и лимитов

**Действия:**
1. Проверить отсутствие `OPENROUTER_API_KEY` — сообщение пользователю.
2. Обработать ошибки OpenRouter (401, 429, 5xx) с понятным текстом.
3. Таймаут запроса к AI (например, 60 с).
4. Если статья слишком длинная — обрезать `content` перед отправкой в модель.

**Результат:** приложение не падает молча при сбоях API.

---

### Шаг 7. Переменные окружения и деплой

**Действия:**
1. Убедиться, что `.env.local` содержит:
   - `OPENROUTER_API_KEY`
   - `OPENAI_BASE_URL=https://openrouter.ai/api/v1`
2. Добавить те же переменные в Vercel → Settings → Environment Variables.
3. Собрать и задеплоить:

```powershell
pnpm build
npx vercel deploy --prod
```

4. Проверить все три кнопки на production.

**Результат:** функции работают локально и на https://referent-pi.vercel.app.
